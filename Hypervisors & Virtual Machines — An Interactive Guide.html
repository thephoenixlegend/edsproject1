01 · Concept

What is virtualization?

Virtualization is the technology that allows one physical computer to run multiple independent virtual computers.

Without virtualization
  • One physical server

  • One primary environment, often under 15% utilized
With virtualization
  • One physical server
  • Multiple virtual machines
  • Multiple independent operating systems

Why it matters: servers once ran a single application each and sat mostly idle. VMware popularised x86 virtualization from 1999 onward, and today almost every public cloud is built on it.

02 · The virtual machine

Understanding a virtual machine

A Virtual Machine is a software-based computer that behaves like a physical computer. To the guest operating system, its virtual hardware looks real.

03 · The hypervisor

The hypervisor: the control layer of virtualization

A Hypervisor is software or firmware that creates, runs, and manages virtual machines while allocating physical hardware resources.

04 · Under the hood

How the hardware makes it fast

Modern hypervisors do not emulate a CPU in software. CPU vendors added virtualization features so guest code runs at near-native speed.

06 · Resource allocation

Divide one server between three VMs

Physical server: 16 cores · 64 GB RAM · 1 TB storage

Real-world scale: the default VM 1 (4 vCPU, 16 GB) matches an AWS m5.xlarge instance. vCPU allocation does not necessarily mean exclusive assignment of physical cores: the scheduler time-slices vCPUs across cores, so total vCPUs can exceed the core count. RAM is stricter, because overcommitting forces swapping or ballooning.

09 · Virtual machines vs containers

A common point of confusion

Containers share the host kernel; VMs bring their own. Cloud platforms often run containers inside VMs to combine both.

AspectVirtual machineContainer
KernelOwn guest kernelShares the host kernel
IsolationStrong, hardware-assistedProcess-level, weaker boundary

10 · Trade-offs

Advantages and disadvantages

Advantages
  • Better hardware utilization
  • Multiple operating systems
  • Reduced hardware costs
  • Flexible resource allocation
  • Easier testing and deployment
  • Simplified infrastructure management
Disadvantages
  • Performance overhead in some workloads
  • Resource contention
  • Host hardware failure can affect multiple VMs
  • Additional management complexity
  • Security risks if misconfigured
